## 0．这次重排得到的主要结论

1. **源UAGMC的E0 K3均值被603坏seed显著拉高。** 该seed Best94.05、平台96.48；其余三个Best约33.58–34.67。旧OD在K3的均值虽明显改善，按同编号seed却只赢1/4；可能是减少坏盆地而非提升典型好平台，二者都值得分开研究。

2. **严格E1的源UAGMC不是所有机场规模都崩溃。** K2有3/4个Best数值低于Ready，但完成率口径不同；K3、K4则4/4个Best均高于Ready，平台差距也更大。这个条件性规律比“模型全都乱飘”更准确。

3. **旧S、AC和直接S＋AC没有在严格E1形成普遍胜源的证据。** 个别seed或K3均值优势应逐项保留，但不能上升为整个机制族已成功。

4. **完整Graph/EventQ在E1相当多条件是稳定但不够好。** 与源UAGMC是不同训练seed，只能比较分布参照；它们也没有稳健战胜增强Ready规则。

5. **120M的E1联合低Best伴随大量未服务。** 比源CO更低不等于全体乘客更快；不能把这些格子当作How已完成。E0带J3名称的模型实际仍是Single。

6. **48M最值得保留的是部分保留能力改善，而非已经获得全局新冠军。** E1 K3的R00已经改善冻结源，R01的额外效果应只算R01−R00；Shared/组合在不同K方向不同。

## 6．归因边界与近期优先级

1. **先统一强在线参照。** 作者函数、Native、Ready必须保留不同名字；同入口、同需求、同权限和同评估边界重放后，再冻结正式比较对象。

2. **优先解释最清晰的两类故障。** 一类是E0坏盆地与R00更新漂移；另一类是120M E1联合服务兑现不足，不强行用一个时间错位故事解释全部。

3. **再验证E1 K3的小增量。** 残差初始化本身已很重要；只对R00加/关一个Shared或AC环节，用独立源checkpoint复核，而不是继续铺方法大全。

4. **把稳定但差的平台单列。** 对Graph/EventQ先检查动作排序、有效信息和通路，不把稳定化当万能修复。

5. **240M/198M回传后按原ID追加同一结构。** 不以当前对话进度判胜，也不重写历史数字；新方法如果使用不同reward/horizon/控制协议必须另层。

这些是基于现有数据的下一步判别顺序，本次没有启动它们。

## 7．复核、数据字典与软件边界

| 字段 | 含义 |
| --- | --- |
| best | 各run在21个DET检查点中最小的已完成者平均旅时，单位分钟 |
| best_completion / best_rpt | 恰在该run自己的Best检查点取得，不把其他点的最好完成率拼上来 |
| late | 实际末步数80%后的5个存档点等权平均；不是原脚本部分入口四点late的混用 |
| u_reference_type | 同编号、跨批分布或冻结checkpoint的比较类型 |
| u_best_gap / u_late_gap | 相对正确U参照的数值差，不能跨比较类型汇成一个效应 |
| best_gap_author | 同环境/K/机队下三作者规则的事后最小CO参照，其他指标来自同一规则 |
| best_gap_ready | 对同权限Ready；非120M明确标记跨入口；缺少机队结果则为空 |
| best_jointly_ready | 同一Best的CO更低且完成率/RPT不劣；事后敏感性，不是已证总体胜利 |
| seed / source_seed | 当前优化seed与48M冻结源训练seed分别保留 |
| campaign / track / archived_member | 来源批次、主比较或机队扫描、归档曲线路径；用于防止重复计数 |

所有病例保留，未自动删除异常值、未填补缺格、未新增训练数据。人物ID/乘客时刻未作为独立n；跨seed均值/SD与完整范围同时提供。本轮归档适配器只取指定CSV/JSON，不执行包中源码或载入pickle/权重。

本报告用统计分析技能约束配对、伪重复和删失，用EDA的来源/缺失审查原则组织数据；其通用工具不支持tar，因此归档读取使用本地有界只读适配器，不声称通用EDA工具验证了压缩包。小样本未进行正态性筛选或显著性寻找。
