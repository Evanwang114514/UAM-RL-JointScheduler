# 五千万预算实验设计：先排除简单解释，不做新模型海选

2026-11-01。性质：固定前瞻实验合同；已写代码，尚未训练，不承诺出现好结果。

## 一页说明

这一轮不是提出“新S/AC/WM/MARL”。它只问：**修正奖励之后，现成PPO能否通过少量合法运行信息学好？剩余损失更像时间信息问题、四座批次问题，还是普通架构就能解决？**

优先顺序：K3关键因子→普通Transformer反驳对照→重复seed→K2/K4边界。所有组一开始固定，不按中途最好结果调整。总训练48格×1,003,520＝**48,168,960步**；50,000,000上限，预留1,831,040步。仿真回放不算PPO训练；中断重做仍计预算。

## 1．为什么这样设计，而不是直接训练SYSTEM/WM

本次诊断的SYSTEM没有稳定闭环收益；无新到达假设改变了未来凑批和竞争，不能把它当真标签。另一方面，972,000个原时间槽全零与尾批修复可改善，提供了两个可检验、低复杂度的假说，但尚未证明新算法必要。

因此训练要从无训练无法回答的地方开始：**输入信息补到策略后能不能被学会，以及两类输入的作用是否独立、是否依赖联合控制。** 不把源模型的旧奖励巨大失败算作新方法提升。

## 2．组别：四臂因子，外加一个普通网络

所有组保留相同原六帧输入。每站额外预留6个当前状态槽，关闭的槽全部为0。LSTM四臂同网络大小、同seed初始权重，额外槽通过同一个无偏置线性残差加到128维时序表示，不加辅助loss、不加额外优化器。

| 臂 | 时间TIME | 批次BATCH | 时序网络 | 必须回答的问题 |
| --- | --- | --- | --- | --- |
| L00 | 关 | 关 | 原LSTM128 | 容量匹配的PT基座 |
| L10_TIME | 开 | 关 | 同LSTM | 已知时间是否真有性能价值 |
| L01_BATCH | 关 | 开 | 同LSTM | 显式四座余数是否足以解释一部分提升 |
| L11_BOTH | 开 | 开 | 同LSTM | 两种信息是否有可复核交互 |
| T11_BOTH | 开 | 开 | 普通Transformer | 同信息下现成注意力编码是否已足够 |

每个臂分别在Single-LQ和J3运行。K3每个控制×每臂4个全新训练seed1701–1704：40格。K2/K4各只做L00/L11×两控制×单seed1705：8格，用于边界观察，不作跨seed或规模普遍规律。

这不是完整的“网络×TIME×BATCH”三因素设计，**没有T00/T10/T01**，因此不能估计Transformer的时间或批次主效应，只能估计T11相对L11的同信息、有限预算替换效果。Transformer参数量单独记录，未宣称严格等参数；LSTM四臂才是容量/初始化匹配的主要归因。

## 3．TIME和BATCH究竟读什么

TIME每候选站四值：已有空闲/充电/已返航空机的最早service-ready离散估计；本站飞机平均剩余充电时间；已承诺地面在途乘客的最近到站倒计时；已承诺空机返航的最近到站倒计时。单位先除60再按训练VecNormalize统计归一化。**不另开焦点OD或access捷径，避免将旧实验已经知道的OD通路收益当作时间收益。**

ready沿用已核对的物理描述符：ceil飞行剩时+ceil充电时间；尚未决定返航目标的飞机不加入任何候选的已承诺供给。601哨兵只表示无当前已承诺供给/到达，不表示真实等待601分钟。它不是完整服务排队时间，也不是精确未来预测。

BATCH每站仅两值：当前站内排队人数mod4，以及“站内排队+已承诺地面在途”人数mod4，除3缩放。**不读取未来还有多少请求、不拿真实CSV末尾信息、不强制最后乘客改站。** 它们是计数的显式算术组织，不能包装成新交通理论。

TIME是一个小型合法信息包，不是把access、charge、arrival四项各自单因素拆开；若TIME有收益，本轮只证明这个包的作用，不能直接唯一归因某个ETA。后续只对仍未识别的项再做诊断，不在本轮增添模型族。

所有新增信息使用当前pre或dispatch时点；不回写过去六帧。无新到达模拟器、未来CSV真值、事后最优动作、尾批离线修复均不进入训练输入或奖励。

## 4．冻结合同：不能偷换环境

| 项目 | 本轮值 |
| --- | --- |
| 基座 | GitHub main已入库30M入口的hash固定自包含快照 |
| 物理 | 严格E1、12架守恒、4座满批、源机场坐标、原充电与V2返航权限 |
| 训练/评估 | 原300人CSV，500/600分钟；时钟和截断原样 |
| 奖励 | 所有组PT_POST：原事件之后的generated-unfinished负人时；不加均衡/利用率奖励 |
| PPO | 5环境×4096，rollout20480，batch512，epochs10，gamma.99，lambda.95，clip.25，entropy.01，vf.5，gradnorm.5 |
| LR | 每run从零，5e-4在完整1,003,520步内线性到0 |
| 时序/策略头 | 原LSTM128，或普通128宽/4头/1层/FF256 Transformer、dropout0；原256×256 actor/critic与J3条件飞机头 |
| 输入残差 | 6K→128无偏置线性层，所有LSTM臂共享结构和初始化；L00输出恒0 |

**这是近期源合同的派生，不是早期40机队、gamma1、10×2048的StageII。** 本轮不改gamma/训练时限，不把折扣回报直接叫完整ATT等价。FullPPO只是优化器；J3不是完整HAPPO/MAPPO复现。

## 5．执行顺序与预算

| 顺序 | 内容 | run数 | 累计训练步 |
| --- | --- | --- | --- |
| P1 | K3，1701/1702，S/J×LSTM四臂 | 16 | 16,056,320 |
| P2 | 同两个seed，S/J×T11 | 4 | 20,070,400 |
| P3 | K3，1703/1704，S/J×LSTM四臂 | 16 | 36,126,720 |
| P4 | 同两个seed，S/J×T11 | 4 | 40,140,800 |
| P5 | K2/K4，1705，S/J×L00/L11 | 8 | 48,168,960 |

同一个seed块内以固定随机数20261101打乱控制和臂的顺序，保存注册表；不把所有好候选先跑、对照留最后。重要对照先成组，不按观察到的成绩晋级。

每格隔离worker；单格失败写FAILED并继续后续格，--resume --retry-failed恢复。每完整rollout保存模型+优化器+归一化+RNG；仿真episode重启，不声称逐bit无缝继续。预算记录失败工作与未落盘尾段上界，超过50M不再开始相应格，不清零账本。

## 6．评价：完成率不许被平均旅时隐藏

新确认bank：保持原300个OD联合多重集、原到达时刻与ID，只重排OD顺序，种子4301–4304；与诊断中的4201–4204不同。代码固定后生成，不用于训练，不按新bank选Best；不声称跨需求分布泛化。

- 每约50k存完整模型。所有检查点至少原CSV eval123；末20%固定检查点同时评估4条新确认顺序。Final额外原CSV eval124。
- 主要归因读数：模型内末20%×四确认顺序平均的固定600分钟RPT，**必须并列完成率、全完成episode比例和整批阻塞标签**。RPT是有删失时的诊断量，不把它改名ATT。
- 全部评估都完成才给该模型对应组的全体ATT，否则null。CO-ATT保留原记录但不单独排名。能否称交通性能胜出，仍要有全体ATT与服务兑现证据，不能只在截断成本赢。
- Final作次指标；完整学习曲线、Best后回退、late波动与最差seed都保留；不按Best选冠军。
- 对四臂作配对：TIME增量、BATCH增量、BOTH增量，以及L11−L10−L01+L00交互；各自在Single和Joint中报告。另算T11−L11，不能把二者差异唯一归因信息。
- 独立单位为训练seed，n=4；窗口、trace、eval123/124不扩充n。先列全部每seed差、均值/SD/范围；若正式做多重推断，预注册对照族并作Holm，不先找最低p。小样本同向不等于充分统计功效。
- 资源拆分写TIMING：采样、网络更新、保存与prepare/finish通信耗时；通信含IPC，不冒称纯物理CPU时间。记录真实FPS与参数量，不能只按训练步数说省算力。

## 7．结果分叉：下一次怎么决策

以下是本轮全部完成后的决策约定，不是中途逐批偷看p值后挑模块。

| 结果 | 可以保留的判断 | 后续动作 |
| --- | --- | --- |
| BATCH有效，TIME无效 | 批服务算术/尾部组织比已知时间输入更优先 | 先追踪服务完整性与最后批次，不硬写时序错配 |
| TIME有效，且不是牺牲完成率 | 合法当前时序描述符有可学习价值 | 细分就绪/到站/服务等待；只补仍未识别的因果问题 |
| L11优于两单因子 | 有限样本上存在交互候选 | 先按独立seed与完整ATT确认，不宣布普适协同 |
| 普通T11已经匹配或超过L11并强于规则 | 不需要专用新架构这个竞争解释很强 | 接受现成Transformer；另找真正交通贡献，不造新模块 |
| LSTM/T11都不能稳定胜READY | 网络结构不是已证明的主要障碍 | 停止继续海选；查剩余运行权限、尾批服务政策、奖励尺度/折扣等可诊断项 |
| 单侧已足够且更稳 | Joint不必成为论文硬要求 | 飞机仍以明确公开的LQ/强规则作控制参照，不把规则当创新 |
| 四臂都差不多 | 当前特征假说未获支持，不代表所有时序问题不存在 | 保存负结果，停止沿这一特征包加复杂度 |

后续大训练的实际意义参考门槛：大多数seed有至少约2分钟/人改善且服务兑现不变差；必须看范围/不确定性与新确认顺序，而非只看3/4同向。2分钟是本项目决策阈值，不是统计定理，也不承诺会通过。

WM仍需证明“合法预测的决策价值”稳定，不能用这次有偏COMMITTED标签直接开训；MARL仍需经验时机/信用组织的直接证据。本轮两者都不实现。

## 8．工程交付和保留材料

单文件train_uam_gap_factors_50m_ONEFILE.py，自包含压缩的30M运行时及源码数据，不依赖另外的矩阵脚本。只在新serial_runs/uam_gap_factors_48run_50m_v1写入。原冻结文件、历史实验、原物理代码都不修改。

自动输出：SUITE_PLAN、TASK_REGISTRY、BANK/hash、逐格manifest/曲线/完整评估、失败和预算账本、MODEL_RESULTS、PAIRED_EFFECTS；结束自动生成DATAONLY包。完整结束额外生成FINAL_REPLAY_MODELS包，含48个最终模型+配对归一化，**不删除原检查点**。

本次验证范围：语法及封装hash、48格预算/因子/顺序、描述符合法信息、确认bank的OD多重集与时刻守恒，7项单元检查通过。按用户要求未在本地创建模型、未跑仿真或PPO；没有伪称服务器已运行或端到端训练已验证。服务器入口有模型/schema/初始化/预算/磁盘断言，出现错误保留日志而不静默改合同。

运行前仍由用户在共享服务器查看top与nvidia-smi；脚本限制自己的CPU线程、5个环境和显式单卡，不终止别人进程。预计训练墙钟取决于实际FPS：若平均600–1200步/秒，纯采样更新约11–22小时，Transformer、评估/保存及共享负载还会增加；不是新代码速度承诺。

## 9．方法学参考与边界

本轮沿用旧清华/交通/AI报告的“先证明剩余损失，普通模型与强规则先行，只有需要预测/协作时才引入WM/MARL”原则，不新宣称阅读大量文献。实验设计/统计技能影响了四臂因子、按seed分块和独立单位；程序性参考Kassis等(2026), Scientific Agent Skills，https://arxiv.org/abs/2609.00065（已核对v2）。这不是创新性证据。

本轮能回答的是**给定预算、给定信息组织下的可学习收益**，永远不能由48次训练证明“所有PPO/Transformer原则上都无法弥补gap”。投稿前仍要独立解决文献新颖性、任务自然性与未见需求泛化。
