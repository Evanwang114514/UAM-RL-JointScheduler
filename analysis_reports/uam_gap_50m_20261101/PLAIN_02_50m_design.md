# 五千万实验，到底在查什么？

白话版｜2026-11-01。解释已经写好、已经开始执行的方案，不增加组别，不改正在运行的代码。这里没有新的实时进度或性能成绩。

## 1．先用一句话讲清楚

**奖励问题先处理过了。这一轮只查：剩下的调度损失，能否通过告诉普通模型“飞机多久能用”和“还差几个人凑满一架”来减少。再用普通Transformer检查：是否根本不需要专门发明新网络。**

所以，这不是五个新方法打擂台。主要是在同一个模型上开、关两类信息；第五组是一个现成网络对照。不同结果都会改变下一步方向，不预设哪组必须赢。

## 2．为什么这里需要训练，而不是继续只回放？

无训练诊断已经告诉我们两件事：原时间输入有遗漏；事后调整少数尾部乘客，确实可能改善服务。

但它没回答：

**如果在当时只提供合法可知的信息，模型能否学会提前避免这些问题？**

事后找得到一个好动作，和模型当场能选到这个动作，不是一回事。五千万实验就是补上这一步。它还不是最终新方法验证，更不能保证一定跑出有创新性的结果。

## 3．两类新增信息分别是什么？

### 第一类：时间信息——不只看现在有几架，还看多久能载客

对每个可选出发站，告诉模型四件事：

1. 按当前已经确定的情况，最早大概多久能有一架可用飞机。
2. 本站飞机平均还要充多久电。
3. 已经选好本站、正在地面路上的乘客，最近一批还有多久到。
4. 已经确定空返本站的飞机，最近一架还有多久到。

旧代码标签是TIME，本文直接叫“时间信息”。这些是近似描述，不是对未来排队的精确答案。

**只算已经知道、已经确定的事。** 不偷读未来CSV，不知道十分钟后会突然出现什么新请求，也不假装知道以后还没作出的派机决定。

### 第二类：四座凑批信息——把简单余数直接告诉模型

飞机必须四个人一批。我们额外告诉模型：

- 本站现有排队人数除以4，余几个人。
- 把已经选了本站、还在地面路上的乘客也加上，再除以4，余几个人。

例如8人余0，10人余2。模型原本可能需要自己从人数中学这个规律；现在是把这个算术结果明确给它。

旧代码标签是BATCH，本文叫“凑批信息”。**它不是神经网络训练时batch_size那个“小批量大小”。** 也不是提前知道最后还会来几个人，更没有强行修改最后乘客的目的站。

这两类信息都有价值的线索，但都还没证明能带来稳定提升。不能因为听起来合理，就默认有用。

## 4．五组不是五套复杂方案

前四组都是同一种小型记忆网络：LSTM。你可以把它理解为“读取最近几帧记录的普通模型”。网络大小和初始设置保持匹配，关闭的信息位置填0，避免把“信息有用”与“模型偷偷变大”混在一起。

| 白话名称 | 告诉时间吗？ | 告诉凑批吗？ | 代码标签 |
| --- | --- | --- | --- |
| 什么都不加的对照 | 否 | 否 | L00 |
| 只加时间 | 是 | 否 | L10_TIME |
| 只加凑批 | 否 | 是 | L01_BATCH |
| 两种都加 | 是 | 是 | L11_BOTH |
| 两种都加，但换普通Transformer | 是 | 是 | T11_BOTH |

标签里的L代表LSTM，T代表Transformer；后面两位依次表示时间、凑批是否开启，1是开、0是关。

最后一组给Transformer的信息，与“两种都加”的LSTM相同。它是用来检验：**现成网络是不是已经足够，而不是为了证明我们必须有新结构。** 两类网络参数量不是严格相等，因此不能把差异全归结为某一种注意力机制。

另外，我们只做了“双信息Transformer”，没做它的其余三个开关版本。所以这一轮不能完整判断Transformer内部哪种信息贡献多少。

## 5．单侧和联合都会做，其他条件不动

单侧是模型选乘客出发站、飞机按最长队规则调度；联合是乘客和飞机两边都由模型作决定。前面的五组各自在这两种控制方式下训练。

每组都用相同的新人时奖励：**乘客已经出现、但还没有到终点，就继续累计耗时扣分。** 不会只给某组额外加“队列均衡”“多飞几架”等奖励。它更贴近服务所有人的目标，但本轮保留原折扣等训练设置，不能称与最终全体旅时数学上完全等价。

飞机仍是12架、四座满批；机场位置、充电规则、空返权限和训练需求不变。**不会为了让某组赢，改机队、改负载或改场景。**

## 6．五千万步是怎么花的？

这里的一“格”，是一个模型从头训练一次；不是一场测试，也不是每个模型训练五千万。

主要检查有三个可选出发站的情况。五组×单侧/联合两种控制×四次独立训练，共40格。

另外，在两个、四个可选出发站时，各做“什么都不加”和“两种都加”的小对照，单侧、联合都做，但每格只有一次训练，共8格。

这里说的两个/三个/四个站，都是**可选出发站数**，还另有一个共同目的站。小规模补充只能看线索，不能因为一个随机种子表现好就说跨机场数都成立。

总共48格，每格实际1,003,520步，合计48,168,960步，余下约183万步作为五千万预算内的中断预留。

执行顺序先把主要开关对照和普通Transformer跑出来，再补足独立重复，最后看其他机场数。**组别一开始就定好，不是看谁暂时好就给谁追加预算。**

## 7．最后怎么读结果？先别看谁的最低点漂亮

### 先看乘客有没有真正送完

每组都要同时看：截止时的人均累计耗时、乘客完成率，以及多少场次把所有人都送完了。

原报告的RPT就是前一项：仿真截止前，所有已出现乘客累计花了多少时间，再除以人数。它方便在有未完成乘客时比较，但不是最终全员平均旅时ATT。后者只有相关乘客都完成后才能给出。

**不能靠不服务最难的人，把“已经完成者”的平均旅时做漂亮。**

### 再看重复训练是否大体支持同一个判断

主要情况做四次独立训练，也就是四个训练seed。四个不是很多，所以会把每次结果都列出，不只挑最好的一次。

同一个模型多跑几条测试，不会变成更多次独立训练。

### 最后看后期是否还能保持，而不是只选一次最低点

主要看训练最后20%的固定存档表现，并保留整个过程。假如曾经很好、最后又明显变差，也要如实记下。

测试还会换四种请求顺序，但总体出行需求与到达时刻保持不变。这能减少只记住原顺序的风险，**不等于已经验证新城市或全新需求分布。**

## 8．不同结果，后面分别怎么走？

| 如果结果是这样 | 人话解释 | 下一步，不追加模型擂台 |
| --- | --- | --- |
| 只加凑批就变好，时间没明显帮助 | 这组环境可能首先难在四座批服务如何组织 | 重点看哪些乘客被拆散、最后一批为何送不完，不硬写成时间错配 |
| 只加时间也能稳定变好，完成率不变差 | 那些已知到达/可用时间确实能被模型利用 | 再查是哪种时间最有用；尚不能说所有损失都由时间造成 |
| 两种都加，比单独加更可靠 | 时间与凑批可能需要一起考虑 | 先检查四次重复是否支持；不能只凭一个好结果宣布两者协同 |
| 普通Transformer已经做好 | 不一定需要专门造一种新网络 | 接受这个结果，交通贡献要从明确问题和运行机制中找 |
| 加什么都差不多，或仍不稳胜强规则 | 这组信息没有证明值得继续扩张 | 不继续把特征包越做越大；回看服务规则、可行动作和其他解释 |
| 单侧已经足够、联合没额外价值 | 这个预算下，飞机不必也交给学习控制 | 可以保留乘客学习＋明确规则调机，不为“联合”而联合 |

这些结论都只适用于本轮信息、实现和预算。没有改善，不等于所有时间方法都无用；Transformer没赢，也不等于证明所有普通Transformer都学不会。

## 9．你最终应该从这轮拿到什么？

不是一张“冠军模型排行榜”，而是三个具体回答：

1. **时间信息补进去后，有没有可重复的真实服务收益？**
2. **四座凑批是否比我们之前反复讨论的时间表示更关键？**
3. **这些信息是否用普通网络就够了，还是仍有清楚、值得解决的困难？**

如果连这三个问题都没分清，后面上世界模型或新多智能体算法，就很容易重新变成抽模型。

截至用户最后提供的2026-11-01 16:48进度，48格中19格训练和评估完成，0失败；16:54第20格正在训练。**这只是历史运行进度，没有本轮性能结论，也不是本次查询了服务器。** 技术版开头的“尚未训练”是它在启动前写下的状态，不应拿来覆盖后面的启动日志。
