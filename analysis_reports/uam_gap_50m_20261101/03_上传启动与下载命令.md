# Windows上传、服务器启动与结果下载

只需上传一个自包含脚本。不要把Windows命令粘在SY@服务器终端中，也不要把Linux命令粘在C:\Users\w>中。

## 1．本地Windows CMD：上传

```cmd
cd /d "E:\Study Files\github\UAM-predict\UAGMC-main"
scp -O -P 10111 "train_uam_gap_factors_50m_ONEFILE.py" SY@22.tcp.vip.cpolar.cn:/home/SY/uam/UAGMC-main/train_uam_gap_factors_50m_ONEFILE.py
ssh -p 10111 SY@22.tcp.vip.cpolar.cn
```

## 2．登录后的Linux终端：直接启动

先查看共享资源，无重度占用再启动。显卡0不是经AI现场确认的空闲卡；脚本另外检查至少4GiB空闲且GPU利用率低于60%。不足时不开始自己的新格，不影响别人进程。

```bash
cd /home/SY/uam/UAGMC-main
top -b -n 1 | head -n 20
nvidia-smi
mkdir -p /home/SY/wyw/logs
nohup env CUDA_VISIBLE_DEVICES=0 OMP_NUM_THREADS=1 MKL_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1 /home/SY/wyw/conda/envs/uam_server/bin/python -B -u train_uam_gap_factors_50m_ONEFILE.py --resume --retry-failed --device cuda --eval-device cpu >> /home/SY/wyw/logs/uam_gap_factors50m.log 2>&1 < /dev/null &
echo "本次PID：$!"
```

没有另设smoke/短训/手动晋级。48格按固定优先级运行，单格失败不阻断后面的格。若已有同名父进程，文件锁会拒绝重复启动。

## 3．服务器：进度和压缩

```bash
cd /home/SY/uam/UAGMC-main
cat serial_runs/uam_gap_factors_48run_50m_v1/progress.json
cat serial_runs/uam_gap_factors_48run_50m_v1/RUNNING.json
tail -n 25 /home/SY/wyw/logs/uam_gap_factors50m.log
```

正常结束会自动生成DATAONLY和FINAL_REPLAY_MODELS两个包。中断后仍用第2段同一条启动命令恢复，不创建新版本覆盖已完成格。只想重新打包已有数据时（确认没有父进程运行）：

```bash
/home/SY/wyw/conda/envs/uam_server/bin/python -B -u train_uam_gap_factors_50m_ONEFILE.py --resume --phase pack --device cuda --eval-device cpu
ls -lh experiment_archives/uam_gap_factors_48run_50m_v1_DATAONLY.tar.gz experiment_archives/uam_gap_factors_48run_50m_v1_FINAL_REPLAY_MODELS.tar.gz
```

FINAL_REPLAY_MODELS只在48格全部训练评估成功后自动产生，不用PARTIAL包冒充完整模型集。
