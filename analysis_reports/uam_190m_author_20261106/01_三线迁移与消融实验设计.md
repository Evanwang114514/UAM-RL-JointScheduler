# 三条实验线：作者方法迁移、核心机制消融与交通结果核查

2026-11-06｜设计已写入代码；本报告不代表新训练已经执行。

## 1. 这次到底要得到什么

不是再寻找一个偶尔最低的平均出行时间。要回答三个有明确对照的问题：

1. **HAPPO的收益，是否确实需要它的顺序策略更新，以及乘客、飞机各自独立的策略？** 如果同配置MAPPO相当，就不能把收益主要归给顺序更新。
2. **MARIE迁移后，跨主体的信息聚合是否真的帮助了模型和控制？** 完整版、关闭聚合、只保留本主体聚合形成递进对照。
3. **DIMA的顺序动作条件建模是否比普通联合条件建模更适合我们的两阶段决策？** 优先完成作者原文的核心对照，再检验顺序、想象长度。

Dreamer不再占主要预算，只补表示学习的必要对照。最终结果允许是保留、降级或停止，不因某个方法失败而临时添加新方法。

本轮是“性能优先、消融约束解释”的方法迁移实验，不预设新的交通创新已经成立。消融变差可以支持某机制在这套实现下有用；仍须结合具体运行损失，才能讨论交通论文贡献。

## 2. 继承哪些事实，不再重复哪些工作

此前热点组每种方法4个训练种子、每个模型约100万真实物理步。在已查看的确认顺序中，截止成本约为：普通PPO＋Transformer 63.85，MAPPO 60.57，HAPPO 59.92，Dreamer 92.61。HAPPO相对PPO有正面信号，但相对MAPPO的平均差只有约0.65，原先区间跨过零，不能宣称顺序更新已经被证实。

Dreamer的坏种子并不只是最后几个乘客的问题：已有正常需求阶段的分流偏置。因此本轮不再把“尾批清理”设成主线。

旧实验完整保留，只作历史锚点，不重跑相同旧任务。现在新建种子、新建训练长度，且配套必要完整对照；这不叫把旧模型续到新预算。旧回放里的7401—7404顺序已经看过，本轮也不会重新称它们为未接触测试。

奖励修正保留为共同基础，不拿来作本轮核心创新。增加时间信息、单独收尾、座位分配、充电设施、增加机场等，均不另开主轴。

## 5. 物理、信息、训练的公平边界

采用近期实际运行的E1、3个出发候选、12架守恒飞机、既有PT_POST人时奖励、原需求和生命周期。**不是旧交接材料里的S3、40架机合同**，两者不得混表。不会改奖励、需求分布、机场位置或容量来帮助某个方法。

所有方法都只读取已揭示需求及已承诺状态；两阶段执行权限相同。世界模型中的两个主体不是两架飞机，而是乘客分流决策者与飞机调机决策者。轮流决策时非当前角色只允许Noop；角色标记是已知执行阶段，不是额外未来信息。

MARIE/DIMA走作者离散动作分支。代码里沿用STARCRAFT枚举只是选取原有离散算法路径，不启动星际环境。训练采样保持完整交通回合交给原learner，由其原N_SAMPLES、MIN_BUFFER_SIZE及更新次数决定训练，不为了加速减少模型更新、去噪步骤、层数或改成简化PPO。

必要适配：500分钟训练截断与真正全员完成分开标记，回放边界仍保留，不能把时间上限教成环境死亡。两条决策记录的折扣折算为一个物理分钟的0.99。作者损失、归一化和网络配方并不全部相同，因此跨算法比较是整套方案的比较；只有匹配消融才用于相应机制解释。

保留作者默认想象记录长度：MARIE/DIMA的15条记录在此相当7.5个物理分钟；Dreamer完整组30条记录相当15分钟。不能把它们都含糊叫“15分钟模型”，也不声称模型架构已完全控制。

## 6. 怎么评，怎样解释每一次选择

每个模型在10%、25%、50%、80%、85%、90%、95%、100%八个固定位置评估，主指标只使用最后五点。每点4条开发顺序×2个策略抽样种子；最终模型另外在8301—8304四条条件重排顺序×3个抽样种子上确认。后者不是新需求分布，也不是整个研究项目从未接触过的最终测试。

不按最低点选模型。先在模型内汇总，再在独立训练种子间配对：均值、标准差、每个种子差值、区间、精确符号翻转结果。8种子也不是巨大样本；4种子补充组只给有限证据，不按显著性最低者挑冠军。

主要交通量是共同截止下的全体乘客人时成本：每分钟系统里尚未完成的人数累加，再除以已生成人数。评估600分钟参数的既有实现实际到601分钟结束，所有组同口径。全员完成时另报真实平均出行时间ATT；未全完成时ATT为空，不能用仅已完成乘客的均值冒充全体ATT。

额外输出包括：逐人截止成本、90%/95%分位成本、真实乘客分流次数、实际有多个调机目标的选择机会、这类机会中的意图投影率，以及逐分钟实际选择日志。没有选择机会的空决策不算“错误选择”。历史READY乘客规则＋最长队调机在相同口径重新评价，但它是启发式，不是最优下界。

还有两类不增加训练步数的配套检验：

1. **共同数据上的世界模型预测。** MARIE/DIMA在同一合法规则轨迹、同一组实际动作上，检查1、5、15物理分钟的开放环预测误差。这样不会把“坏策略走到了难预测的状态”直接误判成“模型本身更差”。原始向量不同维度量纲不同，整体RMSE只作辅助，不作为交通价值正确的证明。
2. **固定第90分钟的一次决策替换。** HAPPO/MAPPO/PPO及MARIE/DIMA最终模型，重新执行共同前缀；先强制重现原动作验证结果相等，再比较3×3个乘客/飞机意图组合，之后继续同一冻结策略。记录系统成本差、受益/受损人数和逐人人时变化。候选仍受原物理投影，不凭空增加权限。这是一次干预的闭环总效应，不是在线可用的新方法，也不是CED或ASE的责任路径分解。Dreamer本轮不加入这项随机状态复演，以免未经核实的JAX状态恢复污染归因。

这只是机制解释的补充窗口，不能凭一个窗口代表整段运营。诊断失败单独保存，不把失败结果写成零误差，也不抹掉已完成训练。

## 7. 跑完怎样决定下一步

| 结果组合 | 后续决定 |
|---|---|
| 完整方法在确认顺序稳定优于普通RL/READY，关闭核心机制后明确变差 | 保留该路线；围绕哪些真实运营选择得到改善，做聚焦交通验证，再谈自研增强 |
| 方法整体较好，但主要消融与完整版接近 | 方法可作有效基线，不能把被消融机制当主要贡献；不再为同机制继续堆模块 |
| 共同预测误差改善，交通成本不改善 | 模型更准确不等于决策更好；不据此自动加大预算，需要先定位价值或策略学习环节 |
| HAPPO与MAPPO接近，二者都优于PPO | 保留多主体控制信号，不宣称顺序更新必要；后续优先简单方案 |
| 固定顺序互有胜负、随机顺序无稳定优势 | 不能强讲“异步时间含义已解决”；把顺序当场景相关因素 |
| 实现完整但同预算持续无收益，且关键消融也无明确方向 | 停止作为主线，不自动切换下一篇热点 |
| 缺依赖、接口报错、未达到计划步数或无有效模型更新 | 只判工程未完成/预算未完成，不判文献方法无效 |

本轮不会预先强迫“单个PPO学不到”。需要的是同权限、合理预算下的可复核增量，以及与关闭机制一致的证据。交通解释要落到具体服务过程和个体代价，不能停留在“考虑未来更好”这种PPO原本已涵盖的笼统说法。

## 8. 耗时、并行、恢复与交付边界

第一文件里非Dreamer约1.199亿步，按旧3.1—4.0百万物理步/小时粗算约30—39小时；Dreamer约1606万步，按旧0.65百万/小时约25小时。合计仅训练就约55—64小时，另有固定回放、模型保存、共享资源等待。不能承诺55小时完成全套。

MARIE/DIMA没有本项目的实测速度。作者别的任务耗时不能直接换算成这里的FPS；保持原模型和更新量时，2500万预算可能需要很多天甚至更久。脚本持续输出真实FPS、真实步数和模型更新轮数，拿到本项目曲线后才能可靠修订结束时间，不能偷偷缩模型或把想象步数算成真实步数。

三个文件可以同时启动三个父进程，但24GB单卡不保证三个GPU工作进程同时驻留。共同显存准入账本会等待空余，不因GPU瞬时利用率高而退出，也不终止其他用户的任务。当前保守预留：普通主线3GiB、Dreamer至少5GiB、MARIE17GiB、DIMA5GiB；实际需求超出时按工程失败保留日志，不自动缩模型。启动前用户仍须top和nvidia-smi观察共享服务器。

支持中断恢复：HAPPO恢复模型、优化器、归一化、随机状态；世界模型还恢复回放缓存。仿真回合重新开始，不承诺位级相同。完整格自动跳过，单格工程失败不阻止其他格；需要重试时保留原错误记录。已完成世界模型格释放自己新建的巨大恢复缓存，最终和固定检查点保留，历史实验一律不动。

每条线自动生成DATAONLY和FINAL_REPLAY_MODELS两个包。完整训练缓存不随包分发；它不是可从DATAONLY恢复的模型。作者外部源码不随结果包再分发，用固定提交、适配审计、入口文件复核。

本地已完成的检查仅为：入口语法、预算和种子合同、作者补丁定位、作者原件哈希不变、Dreamer评估插入可编译、保守中断计费及打包边界。**未连接服务器，未进行GPU训练，尚不能称“迁移运行已验证”或“性能已确认”。** 脚本会将实际包版本、配置、错误和更新统计保存到各任务目录。

操作命令见同目录《02_上传启动下载命令.md》。每条实验一个Python文件；不需要把旧矩阵脚本一起上传。
