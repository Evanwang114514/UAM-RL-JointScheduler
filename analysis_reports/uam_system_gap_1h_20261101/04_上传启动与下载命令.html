命令：本地上传，服务器直接正式运行

AI没有连接服务器，没有执行回放或训练。新文件自足封装冻结运行时，不依赖其他矩阵脚本的本地版本；仍需要服务器上轮诊断的冻结输入和原始核验记录。服务器路径按用户最近确认的/home/SY/uam/UAGMC-main，不是早期迁移路径。

1．本地Windows CMD上传

cd /d "E:\Study Files\github\UAM-predict\UAGMC-main"
scp -O -P 10111 "diagnose_uam_system_gap_1h_ONEFILE.py" SY@22.tcp.vip.cpolar.cn:/home/SY/uam/UAGMC-main/
ssh -p 10111 SY@22.tcp.vip.cpolar.cn

2．登录后在服务器Linux终端运行

先查看共享资源，确认没有别人重负载再执行nohup。这里是直接正式诊断，没有单独smoke或短训练。CPU两名工人各一线程，不需要分配GPU。环境变量CUDA_VISIBLE_DEVICES为空仅是此CPU诊断的资源隔离，不是本地5070不兼容规则。

cd /home/SY/uam/UAGMC-main
top -b -n 1 | head -n 20
nvidia-smi
mkdir -p /home/SY/wyw/logs
nohup env OMP_NUM_THREADS=1 MKL_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1 /home/SY/wyw/conda/envs/uam_server/bin/python -B -u /home/SY/uam/UAGMC-main/diagnose_uam_system_gap_1h_ONEFILE.py --wall-seconds 3600 --workers 2 --resume --retry-failed >> /home/SY/wyw/logs/uam_system_gap_1h_20261101.log 2>&1 < /dev/null &
echo "启动PID：$!"

同输出目录有自己的父进程时会拒绝重复启动。不使用pkill/killall，不终止别人的进程。输入模型会前后校验，所有新结果与缓存只在新输出目录。

看进度：

cat /home/SY/uam/UAGMC-main/workspace/artifacts/uam_system_gap_1h_20261101_v1/progress.json
tail -n 30 /home/SY/wyw/logs/uam_system_gap_1h_20261101.log

3．结束后自动压缩；服务器确认包可读取

脚本会自动打包实际完成的数据、日志、清单和本轮入口；不带模型、私有运行时工作副本。无需额外压缩整个项目。

cat /home/SY/uam/UAGMC-main/workspace/artifacts/uam_system_gap_1h_20261101_v1/SESSION_END.json
tar -tzf /home/SY/uam/UAGMC-main/workspace/artifacts/uam_system_gap_1h_20261101_v1/uam_system_gap_1h_20261101_DATAONLY.tar.gz > /dev/null && echo "本轮数据包可读取"
ls -lh /home/SY/uam/UAGMC-main/workspace/artifacts/uam_system_gap_1h_20261101_v1/uam_system_gap_1h_20261101_DATAONLY.tar.gz

PARTIAL也有包，可以先分析。若希望继续未完成单元，重新执行第2段启动行；这会记录第二次会话的额外时间，不把两小时称成一小时完成。

另开本地CMD；不要把这一段贴在Linux的SY@...提示符后。

if not exist experiment_archives mkdir experiment_archives
scp -O -P 10111 SY@22.tcp.vip.cpolar.cn:/home/SY/uam/UAGMC-main/workspace/artifacts/uam_system_gap_1h_20261101_v1/uam_system_gap_1h_20261101_DATAONLY.tar.gz "experiment_archives\uam_system_gap_1h_20261101_DATAONLY.tar.gz"
