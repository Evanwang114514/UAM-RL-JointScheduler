# 一小时无训练诊断：到底是哪类具体选择还没有做好

日期：2026-11-03。状态：代码已交付，实验未由AI启动，下面没有伪造本轮结果。

## 一句话说明

这次不是再问“能不能找到更低的平均时间”，而是同时检查三种可疑错误：**乘客还在接驳路上，模型是否选错了机场；飞机动作是否真的改变了服务；前后两次选择是否必须配合才能改好。** 再用一个很简单的合法预测规划，检查这些事后发现能不能实际利用。

不增加时间信息、不训练新网络、不改乘客需求、机场、飞机、座位、充电或奖励。收尾问题只作排除项，不作为本轮主线。

## 1．为什么值得再做，而不是重复旧诊断

已交付的上一轮《本轮无训练诊断分析与方向共识》核对到：

| 已有事实 | 对本轮的直接影响 |
|---|---|
| 上一轮细查104个独特状态，1,060次分支，实耗约5分钟 | 本轮目标约1,080个状态槽、约一万次分支；不是拿名义30分钟直接乘十 |
| 1,104次有效调机机会中，257次没有新乘客 | 必须补查“没有乘客新决策，但飞机可以调度”的时刻 |
| 乘客事件样本里，同一时刻联合修改比较好单改的额外空间只有17人·分钟 | 不预设“上多智能体就一定有价值”，重点补查跨时刻配合 |
| 短窗口最好动作与完整后续最好动作常不一致 | 每个候选保留完整后缀，不靠前60分钟宣布成功 |
| 简单合法预测选出的动作不稳定 | 必须包含在线可利用性对照，不能只有事后知道未来的改进 |

这些都是旧诊断的已观察事实，不是本轮新发现。原报告：`analysis_reports/uam_semantics_followup_20261102/01_本轮无训练诊断分析与方向共识.md`，核对位置包括第1、3、4节。

## 2．本轮具体跑四项

### A．延迟有没有被正确利用

你的最初想法保留：**选择机场发生在前，真正加入队列发生在后。** 当前队列短，不代表乘客到达时服务快。

做法：在同一个真实状态，把当前乘客分别分到三个合法机场；每次只改变本次选择，后面继续由同一个策略接管。记录每条分支的实际入队、登机时刻和全体乘客净人时。

“人时”就是把每一分钟尚未完成出行的人数加起来。例如10个人各多等3分钟，就是30人·分钟。它会把他人被拖慢的代价也算进去，不只看当前乘客。

重点看：

- 接驳延迟大、不同机场接驳时间差别大时，原策略是否仍反复选到较差候选。
- 前几分钟看着更好，是否在乘客入队以后变得更差。
- 把各候选放在同一个绝对时间边界比较，检查损失主要是在接驳生效以前还是以后出现；不能用候选A的5分钟直接对比候选B的20分钟。
- 一个只看当前队列的简单打分，与已有READY打分意见相反时，普通模型选了哪边，真实后续哪边更好。
- 具体谁提前登机、谁被拖慢，净收益是否仍为正。
- 模型是否把很高的选择概率放在一个反复较差的候选上，还是几个候选本来就差不多。这里的动作概率不是“正确率置信度”，不能混为一谈。

READY不是新算法：它是已有的“把乘客接驳、正在到来的乘客和飞机可服务时间一起粗略估算”的在线规则。当前队列打分也不是数学最优。两种代理之间的比较同时涉及在途乘客、接驳和服务估计，**不能把差值全部归因于纯粹的延迟因素**。

**能回答：** 模型在延迟相关的实际选择上是否仍有可重复错误。

**不能回答：** 网络内部有没有某个“延迟神经元”，或移除某个输入后重新训练会怎样。本轮不做这类需要重新训练的问题，也不把“延迟存在”直接写成“PPO没学会延迟”。

### B．动作是不是真的可控、真的有效

“能输出一个飞机目标”和“真的改变了飞机的执行结果”不是一回事。

做法：在真实dispatch暂停位置重新取得合法目标，逐个覆盖动作，再回到相同后续策略。特别补查没有新乘客的调机机会。

依次检查：

1. 合法目标是否不止一个。
2. 换目标后，实际飞机位置、目标或空飞出发是否改变；若首分钟相同，完整执行链仍保留，不能直接判为永久无效。
3. 变化有没有让乘客更早登机，还是只多飞了一趟。
4. 当前乘客、已经在系统里的人、后来正常生成的人，各自得到或承担多少人时变化。
5. 把后续策略改为READY后，首次动作的好坏是否明显改变。首次原动作保持不变，不偷换为READY的首次动作。

**能回答：** 这个动作具有多大实际控制效果，以及其好坏多大程度依赖后续补救。

**不能回答：** PPO训练时的信用分配是否一定有问题。发现物理可控性不等于证明训练梯度正确或错误；新信用分配算法是否有效需要训练，暂不在这里做结论。

### C．两次选择是不是必须配合

这就是上一条对话提出的候选：某一次乘客选站与之后某一次飞机回流，是否单改都没用、配合才有用。

同一个起点做四条回放：

| 回放 | 本次乘客选择 | 后续某次合法调机 |
|---|---|---|
| 00 | 原选择 | 原策略 |
| 10 | 换候选机场 | 原策略 |
| 01 | 原选择 | 换目标 |
| 11 | 换候选机场 | 换目标 |

第二次修改只允许发生在原控制权限下的真实合法机会：不早于起点后1或10分钟，再等最多10分钟，找到具有多个合法目标的时刻。不能凭空增加起飞机会、取消已在路上的航班，或让乘客重新选站。

前一个动作可能改变后面有没有调度机会。对此，全部记录都保留；只有两条B干预都真实触发、改变目标，且在同一时刻执行的“共同合法机会子集”，才计入严格的四臂配合标签。其他情况单列为机会改变或无实际覆盖，不能凑成交互成功。

这一共同合法子集是干预后的特定子集，不代表全系统平均效果。脚本保存全部分母，不只保留成功案例。

本轮把“10人·分钟”作为探索性容差，不是公认效果阈值。若两种单改改善都不超过10，而配合改善超过10，暂记为“需要配合的案例”。还必须检查正常运营段的净收益、跨种子重复和他人的代价，才能讨论研究价值。

收益还会落到具体乘客的登机时刻。脚本记录同站乘客是否提前跨过了一次已观察到的载客出发，但**这不自动证明原来那一班有空位可以搭乘**；只能作为人工复核服务轮次的线索。

### D．不用新训练，简单规划能不能把问题解决

不能只留下“事后知道未来可以更好”的结论。

对4个普通Transformer联合模型及READY联合规则，各跑两条验证轨迹。只在80和180分钟之后的第一个乘客决策机会，最多进行两次小规模规划：

- 从当时已经揭示的历史OD和过去60分钟到达数，重采样8个可能未来。
- 枚举当前乘客选择，以及随后一次合法调机目标；看120分钟。
- 先对8个世界的成本求均值，再选一个方案。不能每个世界挑完最好再平均。
- 在真实回放里执行，比较整场净人时和完成情况。
- 另外把8个世界拆成两半，记录两半是否选到同一个方案，暴露预测抽样不稳定。

这是一个小规模滚动规划对照，不是已证明最优的MPC，也没有穷尽所有预测方法。它有额外计算开销，结果必须和开销一起保留。完整未来CSV只供离线打标签，不能进入这个在线选择器。

## 3．规模、模型和一小时安排

| 项目 | 预设安排 |
|---|---|
| 输入训练 | 已完成的76,677,120步、32模型实验；本轮固定取其中gamma=.99的16个最终模型 |
| 普通模型 | PPO＋LSTM、PPO＋普通Transformer；单侧/联合各4个训练种子1801–1804 |
| 规则 | READY＋LQ、READY在联合权限下的对照；规则只有一个控制器，不是多个训练种子 |
| 物理和奖励 | 全部复用这批模型的E1、K3、12架、四座、PT_POST合同，绝不拿历史40架合同混排 |
| 输入信息 | 仍为这些普通模型已训练使用的合法描述符，不添加任何新信息 |
| 验证轨迹 | 已看过的4303、4304；不碰650x确认顺序，也不叫新测试集 |
| 状态抽样 | 40–260分钟分5层；每模型每轨迹30槽。单侧30个乘客机会；联合20个乘客机会＋10个无新乘客调机机会 |
| 总目标 | 18控制器×2轨迹×30＝1,080个状态槽，约为旧104状态规模的10.4倍；相同物理状态会另外去重 |
| 共同状态对照 | 另加64个槽：16个模型×2轨迹×2个同控制权限的READY状态。与自身轨迹分开，物理hash必须一致；满配合计1,144槽，约11倍 |
| 计算量 | 满配估计约8,000–12,000次分支，受实际合法候选数量影响；另有10场合法规划回放 |
| 运行 | 最多2个CPU进程，每进程单线程；不占训练GPU，不是因为5070不兼容 |
| 时间 | 单会话3,600秒上限，预留约40秒收集和打包；共享负载和打包可能带来少量偏差，不保证跑满所有槽位 |

先让全部控制器各完成6个基础槽，补共同READY状态，再跑合法规划，最后分两轮各补12槽。这样不会先把一个模型查得很细，却没有时间看其他种子。某层没有足够真实机会就明确报告缺样，不从别处挑坏状态补齐。

共同状态只改第一步为被测模型的选择，后续统一由READY继续，另用READY原选择做克隆参考。它能排查“只是走到不同状态”的混杂，但只有少量共同状态，不能直接代替全场方法排名。

脚本自动保存进度、逐状态结果和数据包。到时是`BUDGET_PARTIAL`而不是伪装完成；同命令`--resume --retry-failed`继续。完成的状态不覆盖，旧失败日志保留。单个任务失败不会结束其他控制器任务。

## 4．什么结果决定下一步训练

| 本轮结果 | 后续处理 |
|---|---|
| 延迟长，但普通模型已经选得合理 | 放弃“再补时间信息”路线；不能因为时间有物理意义就坚持时间网络创新 |
| 某类延迟相关选择在多个种子反复错，强规则也错 | 留下具体错误场景与服务链，核查为何出错；先看合法规划能否利用，再决定是否有针对性的训练价值 |
| 只有较弱模型错，强Transformer或READY不再错 | 优先解决学习接近已知强基线的问题，不宣称交通领域普遍缺口 |
| 飞机按钮经常不产生实际变化 | 先检查控制契约或实现；公平修正所有基线，不把修bug包装成新AI |
| 两次单改没用、配合修改反复减少正常阶段净人时 | 保留跨时刻协同主假说；若合法小规划仍有明确不足，再考虑对应的控制结构或学习目标 |
| 配合收益只有一个种子、触发时刻改变或尾部个别人 | 降级为线索或负结果，不据此开MARL大训练 |
| 合法简单规划已经稳定改好 | 它就是强基线；后续学习需要证明更低在线成本、泛化或剩余具体错误的改善 |
| 只有事后未来有空间，合法预测不稳定 | 先查预测抽样、排序误差；不把Oracle收益当新训练依据 |

**本轮不自动启动任何训练。** 下一轮训练必须回答一个具体未解问题，并先写清对照和失败条件；不是把这次所有候选再做成模型擂台。

## 5．读结果时不能踩的坑

- 1,080个状态槽不等于1,080个独立训练样本。独立复制仍是4个训练种子；同一模型的多状态和两条轨迹是重复测量。
- 抽样状态的最好候选损失不能相加成“整场能提升多少”，几个机制的收益也不能相加分配总贡献百分比。
- 分支是“指定后续策略、指定真实需求后缀”下的条件比较，不是全局最优值。
- RNG每次复位，需求文件配对；但未用实体键重建所有随机过程，动作改变后的随机消耗未必逐项对应，不声称完美共同随机数。
- 未观察到入队、登机或完成的，记为未观察/删失，不填0分钟。
- 未全部完成服务时，全体ATT仍不可定义。另列固定截止累计人时÷生成乘客数（RPT）和完成率，不把已完成者平均当全体ATT。
- `operating_gain`只算固定需求生成期结束前的净人时，避免“正常阶段收益”完全来自尾部；也保存吸收尾部前后的分解，但不因此优化尾批。
- 既有16个模型不是完整UAGMC论文网络复现，不代表所有PPO或Transformer。最新60M和STIN实验尚无本轮确认的完整结果，因此没有偷偷纳入或挑中途模型。

## 6．交付、复用与验证边界

入口：`diagnose_uam_mechanisms_1h_ONEFILE.py`，一个文件。它机械封存了已修复克隆绑定和作者源码隔离的适配层，并校验哈希，不需要上传另一轮矩阵入口。运行时只读取现有训练模型、归一化、最终评估记录和两条验证需求；临时作者环境只在本轮输出下创建。

输入：`serial_runs/uam_credit_horizon_32run_18h_v1`。每个最终模型必须重现它原来的验证记录；克隆参考必须等于原轨迹后缀，否则该任务保留失败，不能跳过断言给出结果。

默认输出：`workspace/artifacts/uam_mechanisms_1h_20261103_v1`。

结果先读`07_逐模型先读摘要.csv`；其中`own`是各自轨迹，`common_ready`是共同READY状态，两者不能混平均。延迟看02，动作控制效果看03，四臂配合看04，在线规划看05。完整逐乘客成本、首次入队/登机、飞机出发及候选数据在`jobs`。自动包不包含模型、缓存或临时环境。

代码交付前只做语法、封存内容和纯逻辑核对，没有加载模型、没有做交通回放、更没有新增训练。本轮由用户上传并在服务器直接正式运行，不插入单独smoke流程。

## 参考边界

- [PPO原文](https://arxiv.org/abs/1707.06347)：PPO是优化算法；本设计不会把观察到的有限预算错误升级成其理论学习能力限制。
- [HARL，JMLR 2024](https://jmlr.org/papers/v25/23-0488.html)：真正的多智能体算法涉及优势分解和更新机制，不能把多一个动作头或一次配合成功直接称为HAPPO创新。
- 本项目上一轮诊断报告及冻结脚本为本轮直接工程与证据来源；本轮没有重新完成一份交通领域新颖性综述。发现机制后仍需和具体交通文献核对，不能预写“现有研究普遍忽略”。
- 实验设计技能实际用于分层、配对四臂及避免伪重复；软件方法说明参考：Kassis, T., Agarwal, V., He, Y., Patel, D., & Brueckner, A. M. (2026), [Scientific Agent Skills: A Library of Procedural Knowledge for Research Agents](https://doi.org/10.48550/arXiv.2609.00065)。这是流程来源，不是证明本轮假说正确的证据。
