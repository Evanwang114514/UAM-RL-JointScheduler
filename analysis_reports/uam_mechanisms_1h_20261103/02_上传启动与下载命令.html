上传、直接启动、续跑和下载

只上传一个诊断入口。以下路径沿用本轮已经确认使用的本地UAGMC-main和服务器/home/SY/uam/UAGMC-main，不要把Windows命令粘到Linux提示符里。

1．本地Windows CMD上传

提示符应该类似C:\Users\w>或E:\Study Files\...>，不能是SY@...$。

cd /d "E:\Study Files\github\UAM-predict\UAGMC-main"
scp -O -P 10111 "diagnose_uam_mechanisms_1h_ONEFILE.py" SY@22.tcp.vip.cpolar.cn:/home/SY/uam/UAGMC-main/
ssh uam-server

2．进入服务器后直接正式跑一小时

下面是Linux命令，只能在SY@...$后执行。先按共享服务器约定看资源；这是用户观察，不是额外smoke实验。CPU很忙时先不要启动，不终止他人进程。

top -b -n 1 | head -n 20
nvidia-smi
cd /home/SY/uam/UAGMC-main
mkdir -p /home/SY/uam/UAGMC-main/workspace/artifacts
nohup env OMP_NUM_THREADS=1 MKL_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1 /home/SY/wyw/conda/envs/uam_server/bin/python -B -u /home/SY/uam/UAGMC-main/diagnose_uam_mechanisms_1h_ONEFILE.py --out workspace/artifacts/uam_mechanisms_1h_20261103_v1 --wall-seconds 3600 --workers 2 --resume --retry-failed > /home/SY/uam/UAGMC-main/workspace/artifacts/uam_mechanisms_1h_20261103_launcher.log 2>&1 < /dev/null &
echo "本轮PID：$!"

上面的外层日志所在workspace/artifacts已是本项目既有目录；诊断自身会创建独立结果目录。模型推理显式CPU，未设置CUDA_VISIBLE_DEVICES=-1，不是5070兼容性限制。不会因为别人的GPU利用率偶然高就把这个CPU诊断卡掉。

若要降低与训练同时运行的CPU负担，把--workers 2改为--workers 1；一小时内可能完成更少槽，结果会如实标为部分完成。

3．检查进度；需要时原命令续跑

cd /home/SY/uam/UAGMC-main
cat workspace/artifacts/uam_mechanisms_1h_20261103_v1/progress.json
tail -n 25 workspace/artifacts/uam_mechanisms_1h_20261103_launcher.log
pgrep -afu "$(id -u)" '[d]iagnose_uam_mechanisms_1h_ONEFILE[.]py([[:space:]]|$)'

若因时间到而停在BUDGET_PARTIAL，确认上面的进程查询已空，再原样执行第2段启动命令；每次续跑新增一小时上限，完成的状态跳过。不能重复启动两个相同输出目录的父进程，脚本有目录锁。

4．结束后打包

正常结束或预算到时都会自动打包。如果只需要重新汇总打包、不要回放，在没有本轮进程运行时执行：

cd /home/SY/uam/UAGMC-main
/home/SY/wyw/conda/envs/uam_server/bin/python -B -u diagnose_uam_mechanisms_1h_ONEFILE.py --out workspace/artifacts/uam_mechanisms_1h_20261103_v1 --pack-only
cat workspace/artifacts/uam_mechanisms_1h_20261103_v1/SESSION_END.json
ls -lh workspace/artifacts/uam_mechanisms_1h_20261103_v1/uam_mechanisms_1h_20261103_v1_DATAONLY.tar.gz

--pack-only不把部分完成改成完成；会话状态以SESSION_END为准。若原会话被外部硬杀，可能还没有SESSION_END，需要先正常续跑收尾。

5．回到本地Windows CMD下载到项目

在服务器窗口输入exit退出SSH，或者新开一个本地CMD。以下不是Linux命令。

cd /d "E:\Study Files\github\UAM-predict\UAGMC-main"
if not exist "experiment_archives" mkdir "experiment_archives"
scp -O -P 10111 SY@22.tcp.vip.cpolar.cn:/home/SY/uam/UAGMC-main/workspace/artifacts/uam_mechanisms_1h_20261103_v1/uam_mechanisms_1h_20261103_v1_DATAONLY.tar.gz "experiment_archives\uam_mechanisms_1h_20261103_v1_DATAONLY.tar.gz"
tar -tzf "experiment_archives\uam_mechanisms_1h_20261103_v1_DATAONLY.tar.gz" >nul && echo 诊断包可读取

下载后发这个确切文件：

E:\Study Files\github\UAM-predict\UAGMC-main\experiment_archives\uam_mechanisms_1h_20261103_v1_DATAONLY.tar.gz

不需要再传整套模型包。新包包含本轮实际结果、进度、失败记录、规模耗时和入口源码；没有结果之前不能当作已生成文件下载。
