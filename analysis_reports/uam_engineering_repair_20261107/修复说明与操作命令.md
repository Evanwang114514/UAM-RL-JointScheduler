# 11月7日：DIMA恢复与PPO只补评估

## 这次修什么

这不是新实验，不换模型、不加信息、不改奖励、物理环境、训练预算或评估标准。三个原矩阵脚本保持逐字节不变，正在运行的HAPPO/MAPPO和MARIE不需要停止。

1. **PPO已经训完，却在评估入口报错。** 用户提供的2102恢复点是1,996,800步，已达到目标。报错发生在训练函数返回后再次初始化封存环境时。修复工具逐格检查恢复点和`TRAIN_END.json`，另开全新的CPU进程，只加载一次封存环境，然后补齐原有固定存档评估。未满训、缺模型、校验不符的格保留待查，绝不自动补训练或从零重训。
2. **DIMA在世界模型模拟回合重置时，动作掩码类型不一致。** 只在本轮`adapted_author`副本中，把重置返回的0/1可用动作掩码转换成接收张量的类型和设备。原作者仓库不变，模型、损失、想象长度和更新频率不变；修改前后SHA-256、原适配记录和备份都保存。然后调用原DIMA入口恢复，不重新安装环境。

PPO主表里约198.7万步来自较旧的LIVE记录，不代表模型没有训满。是否已满训，以每格校验通过的恢复点及训练结束记录为准。

## 新增文件及验证范围

- `repair_uam_dima_ppo_20261107_ONEFILE.py`：一个工程修复工具，不是额外训练矩阵。为避免覆盖运行中的入口，显式核验并读取现有两个原入口，绝不让它们依赖新的其他矩阵。
- `tests/test_uam_engineering_repair_20261107.py`：8项标准库回归检查。已验证真实DIMA作者副本补丁定位与重复执行幂等、作者原件不变、适配哈希仍通过原检查、0/1掩码转换、满训与旧LIVE区分、模型篡改拒绝、未满训拒绝，以及替身评估流程仅调用一次环境初始化且模型/归一化文件不变。
- 验证没有导入真实Torch，没有运行任何训练或真实模型回放，也没有连接服务器。服务器实际训练、真实评估能否完整结束，仍需运行后日志确认。

### PPO：补评估，并跟随后续相同故障

```bash
cd /home/SY/uam/UAGMC-main
mkdir -p /home/SY/wyw/logs
nohup env OMP_NUM_THREADS=1 MKL_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1 \
    /home/SY/wyw/conda/envs/uam_server/bin/python -B -u \
    /home/SY/uam/UAGMC-main/repair_uam_dima_ppo_20261107_ONEFILE.py \
    --mode ppo --follow \
    >> /home/SY/wyw/logs/uam_ppo_eval_repair_20261107.log 2>&1 < /dev/null &
echo "PPO补评估PID：$!"
```

这会修已满训、且错误确为本次环境二次加载故障的PPO格。`--follow`继续关注本轮剩余PPO格：若原主组又在同一评估入口失败，会补评估；不会启动任何新的训练，不会碰正在被原worker训练的格。所有16个PPO格补齐或原主流程结束后退出；其他错误只保留待查。

工具有独立锁，重复执行不会开两份补评估。PPO最终成绩使用`learn`返回后保存的最终`RESUME`模型，而不是最后一次更新前callback保存的模型。其他预注册时点按第一次达到阈值的固定存档评估，保留请求步数和实际存档步数，不按成绩选模型。

### DIMA：修类型后调用原入口恢复

```bash
cd /home/SY/uam/UAGMC-main
nohup env CUDA_VISIBLE_DEVICES=0 \
    OMP_NUM_THREADS=1 MKL_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1 \
    /home/SY/uam/UAGMC-main/workspace/envs/uam_dima_20261106/bin/python -B -u \
    /home/SY/uam/UAGMC-main/repair_uam_dima_ppo_20261107_ONEFILE.py \
    --mode dima --clear-stop \
    --vendor-dir /home/SY/uam/UAGMC-main/workspace/vendor/DIMA_20261106 \
    >> /home/SY/wyw/logs/uam_dima_repair_resume_20261107.log 2>&1 < /dev/null &
echo "DIMA修复恢复PID：$!"
```

必须用DIMA独立环境的Python。工具会沿用该环境里此前已经修好的nvJitLink库，不碰主环境、MARIE、base或系统CUDA。`--clear-stop`仅明确解除DIMA本实验的暂停标记，并先备份；不会解除其他实验暂停。

DIMA有完整恢复点时按原模型、优化器、回放和随机状态恢复。若之前7000步失败、最后完整恢复点早于7000步，恢复点之后的重复采样仍由原账本计费，不清零已经耗掉的预算。没有可用恢复点的格沿用原入口行为，并保留失败记录；不声称168000步全部得到保留。
